# Контекст проекта: ИИ-профориентация (взрослый тест) — для разработки

Этот документ — полный контекст продукта для передачи в Claude Code перед началом разработки. Прикладывается вместе с файлами: `adult_test_questions_full.md`, `scoring_formula.md`, `llm_schemas.json`, `professions_database_starter.json`.

---

## 1. Что за продукт

Инфопродукт «ИИ-профориентация» — тест на профориентацию для взрослых (позже — отдельная версия для школьников 10-11 классов), который на основе психометрических опросников и свободного интервью генерирует персональный отчёт: разбор личности, разбор карьеры, разбор смысловой/ценностной составляющей. Отчёт генерируется через LLM на основе структурированных данных теста, оформляется как персональная веб-страница (по аналогии с референсным продуктом «Sofia AI», который анализировался при проектировании).

Текущий этап разработки: **первая версия — веб-тест для взрослых** (закрытие вопроса «пройти тест → получить отчёт»). Детская версия и ИИ-репетитор — следующие итерации продукта, сейчас не в скоупе разработки, но архитектура не должна им мешать (общая платформа, общие таблицы пользователей).

## 2. Бизнес-контекст (коротко, для понимания приоритетов)

Воронка: реклама в reels/VK-video → открытый телеграм-канал → телеграм-бот (продажа подписки) → веб-платформа с тестом → отчёт → (в будущем) сопровождение специалиста и апсейлы. Продукт монетизируется подпиской. Команда небольшая, без большого штата психологов — по этой причине сделан осознанный выбор в пользу ИИ-генерации отчёта вместо живого консультирования как основного тарифа (живой специалист — опциональный платный апгрейд, не обязательное звено).

Важное следствие для разработки: продукт должен работать полностью автоматически, без участия человека в цикле «прошёл тест → получил отчёт», это и есть ядро MVP.

## 3. Архитектура теста

Тест начинается **с личного запроса пользователя** (открытый вопрос вроде «Что сейчас беспокоит тебя в карьере или доходе? Что хочешь изменить?») — это смысловой якорь: все последующие разделы отчёта должны логически отвечать на этот запрос, а не быть набором несвязанных блоков.

Отчёт строится из трёх содержательных блоков, которые пользователь просил как обязательную структуру:
1. **Разбор личности** — 16 факторов личности (модель, структурно аналогичная 16PF Кеттелла, но с собственным банком вопросов — не копия лицензированного теста) + этапы развития по возрасту + сильные стороны/зоны роста.
2. **Разбор карьеры** — интересы (RIASEC/Холланд, 6 типов), мотивация (типология В.И. Герчикова, 5 типов) + мотиваторы (модель Пинка: автономия/мастерство/цель), подбор подходящих и неподходящих профессий из базы, идеальная команда, бизнес-направления.
3. **Разбор духовной/смысловой составляющей** — жизненная миссия, ролевая модель (реальный человек с похожим путём), чего избегать, скрытые таланты.

Плюс финальный раздел — план действий (24 часа / 4 недели) и типичные ловушки, явно привязанный к исходному запросу.

## 4. Поток прохождения теста

Порядок: **сначала все открытые вопросы (анкета + интервью), затем закрытые вопросы**. Это осознанное решение: пока пользователь проходит закрытые вопросы (~15-20 минут), в фоне уже готовится черновой LLM-анализ открытых ответов — к моменту завершения теста черновик уже готов, и финальная генерация отчёта ощущается быстрой.

Экраны по порядку:
1. Вступительный экран — объяснение, что за отчёт, как с ним работать (без вопросов).
2. Вступительная анкета — 7 полей (см. файл вопросов), намеренно урезана по сравнению с конкурентами: без точного дохода (только диапазон), без города рождения, без подробного семейного статуса (заменён мягким вопросом про поддержку) — приоритет на приватность и доверие пользователя.
3. Открытое интервью — 5 вопросов.
4. RIASEC (интересы) — 30 вопросов, 4-балльная шкала.
5. 16 факторов личности — 65 вопросов, 5-балльная шкала согласия, разбито на 2 экрана.
6. Мотивация (Герчиков) — 20 вопросов, 5-балльная шкала.
7. Мотиваторы (Пинк) — 9 вопросов, 5-балльная шкала.
8. Экран ожидания генерации отчёта.
9. Страница отчёта.

Итого: 124 закрытых вопроса + 7 полей анкеты + 5 открытых вопросов = ~136 точек ввода, ~18-22 минуты прохождения. Полный текст всех вопросов — в `adult_test_questions_full.md`.

**Обязательные UX-требования:** автосохранение прогресса после каждого блока (тест длинный, нельзя терять прогресс при обрыве связи), возможность вернуться и продолжить, прогресс-бар.

## 5. Механика LLM — два независимых вызова, а не «память» модели

Важно для разработки: у LLM API нет встроенной памяти между запросами — каждый вызов независим. «Память» реализуется на уровне бэкенда: результат первого вызова сохраняется в БД и вручную подставляется в промпт второго вызова.

**Вызов 1 (фоновый, сразу после открытых ответов):** промпт с открытыми ответами пользователя → LLM возвращает структурированный JSON-«черновой портрет» (см. `draft_persona_schema` в `llm_schemas.json`) → сохраняется в БД, привязан к session_id. Запускается через очередь задач (например Redis+BullMQ или Celery), не блокирует пользователя.

**Между вызовами:** пользователь проходит закрытые вопросы, ответы сохраняются в БД без участия LLM.

**Вызов 2 (после отправки закрытых ответов):** бэкенд сначала считает баллы по формулам (без LLM, чистая математика — см. `scoring_formula.md`), фильтрует базу профессий до шорт-листа (детерминированно, по правилам совпадения RIASEC-кода и трейт-тегов), затем формирует финальный промпт из: чернового портрета (вызов 1) + посчитанных процентов по ~30 шкалам + шорт-листа профессий + исходных открытых ответов (для цитат). LLM возвращает финальный JSON по схеме `final_report_schema`. Рекомендуется разбить это на несколько параллельных вызовов по секциям отчёта (личность/карьера/смыслы/план действий) для скорости и удобства отладки, а не один монолитный запрос.

**Требование к обоим вызовам:** строго структурированный вывод (JSON schema / structured outputs у провайдера), не свободный текст — иначе фронтенд не сможет надёжно рендерить отчёт.

## 6. Как рендерится персональная страница отчёта

Это не уникальный сайт на пользователя, а один шаблон (React/Vue-компоненты), который заполняется данными из JSON конкретного отчёта. У каждого отчёта — уникальный slug/URL (например `/report/r0ysjp`). Фронтенд запрашивает JSON по этому id и подставляет значения в готовые компоненты (карточка черты с прогресс-баром, карточка профессии, карточка этапа жизни и т.д.) — дизайн общий для всех, различается только контент.

## 7. Схема базы данных (укрупнённо)

`users`, `test_sessions`, `open_answers`, `questions` (банк вопросов с флагом reverse), `closed_answers`, `computed_scores`, `llm_jobs` (очередь и статусы вызовов LLM), `professions`, `reports` (финальный JSON + slug), `report_progress` (чеклист-геймификация), `books_library` (курируемый список книг для рекомендаций — LLM должна ссылаться на id из этой таблицы, а не придумывать книги).

## 8. Данные, которые уже готовы (приложены отдельными файлами)

- `adult_test_questions_full.md` — полный текст всех 124 закрытых + 12 открытых вопросов, с пометками реверс-вопросов и используемых шкал.
- `scoring_formula.md` — точная формула перевода ответов в проценты по каждой шкале + правило фильтрации базы профессий.
- `llm_schemas.json` — JSON-схемы для обоих вызовов LLM (draft_persona и final_report).
- `professions_database_starter.json` — стартовая база из 16 профессий с доходами (часть подтверждена рыночным поиском, часть помечена как оценочная — см. поле `source_note` у каждой карточки) и тегами для алгоритма подбора.

## 9. Важные ограничения и юридический контекст

- Тест собирает чувствительные персональные данные (доход, личные переживания, образование) — нужен явный пользовательский консент на обработку и передачу данных в LLM API третьей стороны (учитывать 152-ФЗ при выборе провайдера/хостинга данных).
- Не давать в отчёте формулировки-гарантии дохода («вы будете зарабатывать Х») — только рыночные ориентиры со ссылкой на диапазон.
- Отчёт должен явно маркироваться как инструмент самопознания, а не клиническая психодиагностика.
- Личностная модель (16 факторов) сознательно не копирует вопросы оригинального лицензированного 16PF — банк вопросов написан самостоятельно на основе определений факторов.

## 10. Что осознанно вынесено за скобки текущего этапа

- Полноразмерная база профессий (сейчас 16 карточек, нужно 40-60+) и её регулярное обновление через API рынка труда.
- Библиотека книг/фильмов для рекомендаций (структура в схеме заложена, содержимое не собрано).
- Детский тест, ИИ-репетитор, тариф «стать специалистом» — не в скоупе первой версии.
- UI/визуальный дизайн страницы отчёта — обсуждалась референсная структура (Sofia AI), но макетов ещё нет.
